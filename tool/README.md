read when running or changing the local design tool, its controls, persistence or presentation command

# Design tool

Run `bin/design-tool path/to/name.design.json`. A file that exists is opened as it is, and a file that does not exist is created as a new design. Without a file the command stops and shows its usage; nothing is remembered between runs. Opening a file never writes to it. Every change is saved at once, and the first write of a run first copies the file to `name.design.bak.json`, replacing the backup of any earlier run; a save that would change nothing writes nothing. `bin/design-restore path/to/name.design.json` puts the backup back, after asking.

The other commands take the file the same way: `bin/design-presentation` makes the presentation and `bin/design-check` checks the file. `bin/design-gallery` and `bin/design-test` build the gallery and run the tests. Each runs from any folder. `bin/design-tool` also takes `--port 4174` or `--no-open`, as does `npm run tool -- path/to/name.design.json`. The dependency-free Node HTTP server binds only to `127.0.0.1`. The command prints its URL and the absolute design-file path, and stops with Ctrl-C. If the port is taken, it says so and starts nothing.

A new design (`new-design.js`) is deliberately plain, and deliberately in need of replacing: a made-up company, Placeholdr, with a made-up logo, Mona Sans for everything, its axes giving display text and labels each their own look, its own Mona Sans Mono for code, one blue-purple for everything, no shadows, no frame and square corners. The rest are the library's defaults. These are the starting point of the tool; `defaultInputs()` remains the generator's fallback for what a design file leaves out.

On the main typeface page each role, Text, Headings, First heading, Display, Labels and Code, chooses a typeface and turns what that typeface has: one slider per axis, the letter spacing, and its alternate letters. Sliders are written from the typeface's axes in `src/fonts/catalog.js` when the role or typeface changes, never during a drag; a slider's value goes back to the default when clicked, and it is underlined while set. A new typeface keeps only the settings it has axes for. Run `bin/design-fonts` to fetch the typefaces again: it holds the list and writes `src/fonts/`.

**Export for AI** writes `DESIGN.md` beside the design file, in Google Labs' open format for describing a design system to AI agents: exact tokens with prose on how to use them, the components and the rules. `bin/design-md path/to/name.design.json` does the same, with `-o out.md` for another path. A `DESIGN.md` it did not write is never replaced. The Start page's **Design brief** opens that file: who the site is for and how it should feel, which the format holds to matter more than the values. `src/design-md/` writes it, and `npx @google/design.md lint` checks it.

The tool is the presentation in edit mode. `pages.js` writes the document: the presentation's pages, in its words (`presentation/copy.json` and the design's sibling `<stem>.copy.json`), with each page's controls in place. Every page runs in the same order: heading, controls, examples, explanation, next page. Every control is written once and stays in the page, so changing a value never rebuilds what is being dragged. A fixed menu has the chapters, the saved status and Light/Dark, with the chapter's pages and **Create presentation** below them.

Beside the document, `preview.js` shows the real sample page in two frames at their real widths, Mobile at 390 px and Desktop at 1440, 1024 or 768 px, because a narrow setting shows only on one and a wide setting only on the other. The sample page shows every typeface role, so each control has something to change: display text and code at the top, then a first heading, and the grey and tints further down. Each end shows its Display and Body sizes and how much of the last setting reaches it (`Follows 94 %`). The modes are Both, Mobile and Desktop; only Desktop is ever scaled, and its figure toggles real size. The ends scroll together section by section, and turning a page of the document takes them to the part it decides.

The divider between controls and preview has one optimal position per mode, computed in `logic.js`: the controls get a comfortable measure and the preview the rest, up to real size. It catches within 18 px and shows it with a heavier grip; a double-click or Home returns to it, and it follows window and mode changes until dragged away. **Full window** lets the preview fill the window. **Own window** opens a real second window to put on another screen, kept in sync over a `BroadcastChannel`; its own controls reach the first window, and closing it brings the preview back.

The interface wears the design it edits: `style.css` uses the generated roles of the page Surface, so Light and Dark and the grey temperature reach every part of the window, and the document's samples use the real component CSS. The tool's own words keep one fixed face and size, so nothing moves while a control is dragged. Every change is saved after a short pause, regenerating the complete design file; there is no Save button. Clicking a logo tile chooses an SVG or PNG; a removed logo gives way to the client name. Tooltips overlay the interface, work on keyboard focus and disappear while dragging.

A dragged control must not make anything flicker. Both ends take the newest design once a frame, and the sample page touches only what changed: a logo rebuilt blinks and moves the header, and an image set again is decoded again. The section in view stays where it is on the screen, whatever happens to the height above it, and transitions are off while a control moves, so each step shows at once. 

The colour sliders keep their own OKLCH values, so a colour outside the gamut cannot move them while they are dragged. The direction slider shows where the shadow falls and the arrow points there; the design file still stores the light's angle, its negative.

The chapters run Start, Colour, Typography, Shape, Frame and Components. Frame has a page each for the header, the footer, the page and the breadcrumbs, with drawings to choose a model from, toggles and lists. The preview changes where it stands (`presentation/src/frame-live.js`), and a button holds the menu or the search box open while it is set. Components has a page for each of the presentation's groups. Their preview is another page, `/catalogue.html`, with every real component, and each page's buttons scroll both ends to one of them.

The type scale is set on a number line from 320 to 1920 px. Each breakpoint has a filled arrow to drag, its width under the line, and above it the base and the name of its scale: the figures can be typed over, the name opens a menu of the common named scales, from Minor second to Octave, and says Custom off them. A drag catches at common widths. The left arrow can reach the right one and no further, and on one width the way the pointer goes says which arrow it took. A hollow arrow says which width the rows below show. `logic.js` owns the line's reckoning, the divider's positions and conversion between absolute displayed steps and the schema's relative steps. Changing a style recalculates both adjacent relative differences, preserving every other style's absolute size. Neighbours may meet but never cross, and each relative difference stays in 0–12.

`server.js` owns validation, atomic saves, logo embedding and local endpoints. Saves regenerate the complete resolved result. A contrast failure keeps the last good preview and disables presentation creation. Presentation creation saves the displayed settings first and returns the full ZIP path. The browser link opens the generated file through the same local server.

The preview is compiled from real Astro components once at startup into `node_modules/.cache/konzilo-tool`. It is rebuilt on the next start so changes to components are included. Browser imports expose only explicitly allowed generator files, the schema, package metadata and UI modules. Mutations require a same-origin session token and JSON; Host and Origin checks reject cross-origin access.

The Start page's pictures show what each place on the sample pages holds. Clicking one chooses the client's own photo: the browser makes it a JPEG of at most 2000 px, so a camera's file does not weigh down the presentation, and the tool keeps it as `<stem>.pictures/<place>.jpg` beside the design file, never in the design file. The folder is the whole record: a file put there by hand under a place's name, from `hero` to `person-4` (`PICTURE_SLOTS` in `presentation/src/samples.js`), counts too, as JPEG, PNG, WebP or AVIF. Remove deletes the file, and the sample takes the place again; the backup does not cover the folder. Until then the places hold the photos in `presentation/pictures/`, and people are drawn in the design's colour. **Pictures** and **None** in the preview's bar choose how the pages are looked at, not the design: without pictures, a hero and a card close up around what is left, and a picture that is the component itself, as in a Figure, keeps an empty place. A video keeps its still.

The Start page also stores the optional introduction, contact name and email. Each relevant page ends with an optional explanation, shown to the client: colours, typefaces, type scale, space and shape, shadow and components. These are `project` metadata; they do not affect the input fingerprint. Textareas have fixed heights so dragging another control cannot change the page's geometry.

For scripts: `node bin/konzilo-design.js presentation examples/example.design.json -o presentation/dist/example-presentation.zip`. Without `-o`, output is beside the input as `<stem>-presentation-<YYYY-MM-DD>.zip`. It resolves inputs afresh without rewriting the source design file. The ZIP holds one self-contained HTML file. See [the presentation guide](../presentation/README.md) for browsing, copy overrides, comments and offline verification.

The build needs no browser. `playwright-core@1.64.1` is a development dependency for tests only, using the already installed Chromium revision 1248. No browser download runs. Integration tests close their browsers and local servers in `finally`; temporary presentation build directories are removed after packaging.
