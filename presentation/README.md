# Approval presentation

`node bin/konzilo-design.js presentation examples/example.design.json -o presentation/dist/example-presentation.zip` writes a ZIP with one file, `example-design-system.html`. Without `-o`, the archive is beside the design file as `<stem>-presentation-<YYYY-MM-DD>.zip`, with `.design` stripped from the stem. The HTML filename uses the project's name as a slug and the `document.filename` copy key. The CLI resolves inputs afresh without rewriting the source. The tool saves first, creates the archive and offers the HTML through its local server.

The HTML opens directly from `file://`. CSS, the font files of the shipped typefaces the design uses, upright and italic, the pictures and scripts are inline. There are no imports, external assets or runtime dependencies. A content security policy refuses network access and form submission. External media uses the real Embed component's local explanation option; it never loads a provider. Custom typefaces use the reader's installed fonts and the declared fallbacks. No browser is used to build the document or ZIP. `tool/archive.js` uses raw DEFLATE from `node:zlib`, CRC32 and standard UTF-8 ZIP headers.

`src/catalog.js` defines 24 pages and component coverage. Hash navigation, previous/next links, back/forward history and arrow keys open one page at a time, reset scrolling and focus its heading. Fields, buttons and disclosures keep their own arrow keys. The sidebar shows the chapters, expands only the current chapter's pages and pins Comments to its foot, so it fits a 700 px tall window. Below 900 px, a menu in the top bar replaces it. Without JavaScript, all pages remain visible in order; interactive specimens explain that they need JavaScript.

Colour and typography lead into space and shape, then components grouped by purpose. Reference tables and licences are collapsed at the end. The presentation uses generated roles for its own type, colours, corners and shadows. All prose has the Narrow measure; specimens use the full column. Owner explanations appear only on their assigned first page, as paragraphs and a byline separated by a rule. Introduction and explanations accept plain text only; blank lines make paragraphs and all text is escaped.

## Copy and project metadata

`copy.json` holds every presentation label, title, lead, instruction, toolbar word and comment-export label. Flat string keys support `{placeholders}`. A sibling `<stem>.copy.json` overrides any subset. For `example.design.json`, use `example.design.copy.json`. `copy-override.mjs` reads it, for the build and the tool alike. A key removed from `copy.json` goes into `retired-copy-keys.json`, the sorted list of every key `copy.json` has had and has no longer: an override written for an earlier version that still holds one builds, and the key is ignored. Any other unknown key fails the build, since it is most likely a typo, as do non-string values and an override that is not an object; the message names the file and the key. Missing values fall back to English. `lang` sets `<html lang>` and `Intl` number/date formatting. Sample content belongs to `src/samples.js` and `src/specimens/` and is intentionally not translated. A design's own menu and footer, written on the tool's Start page, take the samples' places (below).

`project.version` defaults to `1.0`. `introduction`, `contact.name`, `contact.email` and `explanations` are optional, outside the input fingerprint. Explanation keys are `colour`, `typefaces`, `type-scale`, `space-shape`, `shadow` and `components`. Their pages are respectively the colour scale, main typeface, type scale, space, shadow and header. Logos are embedded from data URIs or SVG/PNG paths relative to the design file. The supplied identity is used nowhere in repository configuration.

`menu` and `footer` are the client's own menu and footer words, as the tool keeps them (its README): a tree of `label`, `description` and `items`, and the cells `upper.b1`, `a2` and `b2` and `lower.a1`, `b1`, `a2` and `b2`. `src/frame.js` gives them wherever a specimen has the frame: the header with its link menu and large menu (`headerProps`), the footer (`footerContent`), the Page page's alignment example and whole page, the Shadow page's scenes, and in the tool the sample page. A cell without the client's words keeps the sample's, and the upper band's B2 without them is the top level of the menu shown. Neither ever enters the input fingerprint.

## Real specimens

The Astro build renders the unchanged library components in `src/specimens/`, with the sample photos in `pictures/` and a design's own from `<stem>.pictures/` beside its file, named by address. `inline.mjs` pools specimen styles and bundled controllers, and stores each picture once. The common core, component CSS, fonts and forced-state rules are stored once. The reader inserts these into `srcdoc` only when a page or variants disclosure opens. Controller bundles have private function scopes, avoiding collisions between classic scripts on file URLs.

The Shadow page shows each shadow a site casts in a scene of its own (`src/specimens/Shadow.astro`, `SHADOW_SCENES` in `src/catalog.js`): the header over content scrolled under it, the menu open under the bar, the end of a page over its footer, cards on three Surfaces, and one card at rest and under the pointer. They are the real Page, Header, Footer and Card in a window of fixed height; `specimen.css` sets the header's scroll flags and holds the menu open without a modal dialog, which would take the reader's focus. Each is named by its `shadow.<name>` copy key, and says under it where the design has shadows but casts none there. The header-over-panel shadow has no scene, since the open panel covers it on a site.

The Page page opens with a drawing of the page's layout, above its toolbar, since the switches do not change it (`src/page-sketch.js` and `.css`, `src/PageSketch.astro`). It draws a window of 1440 px and a phone's of 390 px, each to scale in width and with fixed heights: the side margin hatched, the content width's edges dashed through the header, the bands and the footer, a band filled edge to edge, and the Reading Area's three placements (page.md, The Reading Area, point 3), Narrow ruled and the Aside dashed. Every figure is the design's width in that window, as the CSS gives it, and a caption says the rules with the design's figures. The design tool's Page view draws the same markup. Under it, Alignment (`src/specimens/PageLayout.astro`) is a short real page with one band for each placement, its guides drawn by the design's own CSS widths, and then the whole page.

The same build makes the design tool's previews of the component pages, a document each, `catalogue-<page>` (`src/catalogue.js`): they render the same specimens with `catalogue` set, which names each variant by a caption and sets every variant side by side, and `inline.mjs` keeps them out of the report. A specimen's report rendering never changes for them.

Each iframe has a real responsive viewport. Wide fills its column; Tablet is 768 px and Phone is 390 px. Each page has one toolbar for all its specimens, with Wide, Tablet and Phone and Light and Dark as segmented buttons, and where a page has pictures, With pictures and Without pictures; sizes wider than the column are not offered. The toolbar is the document's, not the design's: it stands on the sidebar's Surface, each group of buttons is named by its label key, and the chosen button is plain text colour, never the design's button colour, so a reader can tell the switches from the samples, which only show how they look. Nothing is scaled. Each specimen keeps only its name and a small Comment button. The bordered screen is the frame's window: at Wide it fills the column, and at Tablet or Phone it hugs the frame at that width and the frame's height, under the specimen's name, with only the document's background around it. Frames fit their content at every width, so each shows the whole of it, and the content below follows when a width or mode changes; the whole-page example has a 560 px scrolling viewport for sticky navigation and footer reveal. Header and consent compositions reserve at least 560 px for their overlays. Resize observers keep each iframe fitted to its content. Component appearance stays in `src/components`; presentation composition alone lives here.

## Comments

Comments and drafts save as typed under a localStorage key formed from project name, document filename key and version. The same identity/version shares comments across regenerated copies in a browser; a changed version starts a new review. Storage failure falls back to memory and displays a reminder to send or save before closing. A separate page lists comments by page and includes the reader's name. Editing saves immediately; removing affects one comment. Clearing all comments and drafts requires confirmation.

Mail, Save as a file and Copy export readable UTF-8 plain text, including any unsent drafts. The text names the document, version, date, reader, pages and components. Mail uses `project.contact.email`; above 1800 encoded characters it uses a short note and asks the reader to attach the saved file. No email address means Save and Copy remain available and the mail action explains the missing address. Sending never clears comments. Clipboard access falls back to browser copy support, then offers the file action if copying is unavailable.

## Verification

`npm test` checks the generator's unchanged output, schema, component coverage, copy usage, ZIP integrity and the tool flow. Browser tests use only `playwright-core` with the installed Chromium revision 1248, with no download. They open extracted HTML through `file://`, exercise every page at 1440, 1024, 768, 390 and 320 px, test routing and history, real specimen widths, fonts, shadows, menus, disclosures, consent and comments, and reject console errors or network requests. Normal, primary-only and stress designs are covered. Safari, Firefox and Edge require separate manual verification.

For visual review, take screenshots of every page at 1440 and 390 px and inspect them. Keep `dist/example-presentation.zip`; remove scratch design copies, extracted HTML and screenshots, and close all test browsers and servers.
