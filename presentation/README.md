# Approval presentation

The Astro project renders the actual design-system components and their unchanged CSS. `tool/pdf.js` builds it with `KN_DESIGN_FILE` passed only in the child process environment, inlines the result, waits for fonts and images, opens deterministic component states and prints with screen media. `outline`, `tagged`, `printBackground` and `preferCSSPageSize` are enabled. Every sheet is 1440 × 810 CSS pixels, with a common running head, title and foot. Chromium's sub-point paper rounding is normalised to exactly 1080 × 607.5 PDF points by a length-preserving MediaBox edit; cross-reference offsets remain unchanged.

`src/catalog.js` defines chapter and component coverage, including the compound names in the specification's Build now table. Ramp and contrast pages adapt to the available brand colours. Every page has a stable id used for contents links. Typeface specimens adapt to the distinct stacks in use. The catalogue maps each page to a list of component names and a group. Small related components share a page. The example has 65 pages; adding a second brand colour does not add pages. Chapter templates live in `src/chapters/`, the common shell in `src/layouts/`, and component compositions in `src/specimens/`.

`copy.json` contains all document prose, labels and meaningful generated words. It has flat keys and `{placeholders}`. A sibling `<stem>.copy.json` overrides any subset, including `lang`; unknown keys or non-string values fail the build. For `example.design.json`, the override is `example.design.copy.json`. `lang` drives the HTML language, numbers and dates through `Intl`. Missing overrides fall back to English. Sample business content intentionally stays in `src/samples.js` and `src/specimens/` and is not translated.

All imagery is generated as embedded geometric SVGs using only primary and grey ramps, mostly steps 100–300, with at most one small primary 500 accent. Four landscape and four portrait compositions use calm arcs and planes with closures past the crop. Person silhouettes use primary tints for head and shoulders. The full-picture Hero uses primary 800–950 and grey 900. Overview chips still show all brand colours. The project identity comes only from the supplied design file. Header and Footer specimens show a labelled logo alone, or the name alone without a logo. Optional string `project.version` defaults to `1.0` and supplies the cover and every page foot; the generator version is never document copy. `project.logo` and `project.logo-dark` accept SVG/PNG data URIs or paths relative to that file. Assets, CSS and component scripts are inlined; no external requests are permitted during printing. The two recommended typefaces are bundled locally. Other families use installed fonts and their declared fallback stacks.

`inline.mjs` creates forced state selectors with css-tree from the unchanged component stylesheet. The browser opens Header panels and Consent settings through the real controls. Every component specimen gets its own viewport, which contains fixed and sticky elements and preserves vector text. The responsive comparison uses three real 390 px windows at 100%, with their height deliberately cropped by the stage. Four landscape compositions, a panoramic image and four abstract portraits are generated from the current ramps.

Content pages use the design’s own wide rail, centred on the 1440 px page: 120 px margins for the 1200 px example rail. Running head, title and foot align with real component content. The title zone is at y=72–184, the stage at y=200–762, and the foot at y=780. Full-width iframes use a 1440 px viewport at 100%. The stage mode is `fill`, `centre` or `top`, chosen in the catalogue. Only settings that exceed the available stage trigger shrinking and a visible percentage note. Every example page stays at 100%; the stress fixture deliberately exercises the fallback.

The fit helper measures page, introduction, specimen and text ranges after layout. The command returns warnings by page number and title while still writing the PDF. Body text remains vector text. Headings inside specimens are presentation-only in the PDF outline; chapters and page titles remain navigation entries.

Button and Link pages show four states: default, hover, focus and active. Form fields retain disabled examples, including visibly disabled native select and checkbox controls. Panel autofocus is blurred before printing; forced focus examples remain visible. Shadow strength reads barely visible below 25, discreet below 60, otherwise strong; hardness reads soft edges below 30, firmer edges below 70, otherwise hard edges. Existing copy keys stay stable; two middle-range shadow labels are added.

The tuned typeface specimen uses compact spacing to stay at full size. Band uses three equal stage sections (tint, brand and inverse), with presentation-only vertical padding. Callout uses four rows with filled messages left and outlined messages right. Closing steps sit in the lower half as a bookend to the cover. These compositions leave library component styles unchanged.
