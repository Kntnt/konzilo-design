# Variable typefaces for web design roles

## Lora

**Yes: Lora is a genuine variable family.** The [Google Fonts family metadata](https://github.com/google/fonts/blob/main/ofl/lora/METADATA.pb) lists [upright `Lora[wght].ttf`](https://github.com/google/fonts/blob/main/ofl/lora/Lora%5Bwght%5D.ttf) and [separate variable italic `Lora-Italic[wght].ttf`](https://github.com/google/fonts/blob/main/ofl/lora/Lora-Italic%5Bwght%5D.ttf). fontTools reads a real `fvar` `wght` axis from 400 to 700 in **each** file, with no `opsz`, `wdth` or italic axis. Full-file WOFF2 compression measured 85.2 KB upright and 91.6 KB italic. The [OFL text](https://github.com/google/fonts/blob/main/ofl/lora/OFL.txt) reserves `Lora`.

**Method.** I inspected the published font binaries with fontTools, including `fvar` axes, Unicode cmap, default digit advances and GSUB features; for TTFs I measured full-file WOFF2 output from fontTools/Brotli. KB means 1,000 bytes, rounded to 0.1; sizes are not Latin subsets. “Tabular” means a `tnum` feature or equal default advances for 0–9; the latter does not prove every variable instance. The OpenType column reports GSUB tags: `lnum` selects lining figures, `onum` oldstyle figures, `smcp` small caps, and `c2sc` caps-to-small-caps; `ss##` and `cv##` mean one or more stylistic sets or character variants. `(R)` or `(I)` marks a feature found only in the upright or italic file. A missing `lnum` tag does not establish that default numerals are oldstyle. Every listed font file contains `å ä ö Å Ä Ö`, `æ ø`, accented Western Latin, 0–9 and the tested common punctuation. [OFL 1.1](https://openfontlicense.org/open-font-license-official-text/) and [Apache 2.0](https://www.apache.org/licenses/LICENSE-2.0) permit commercial use and redistribution; the listed files can be self-hosted with no runtime request to a third party. A subset is a modified font, so an [RFN normally requires renaming it](https://openfontlicense.org/webfonts-and-reserved-font-names/). A plain WOFF2 conversion that changes only compression may keep the original name. Quality and role fit below are editorial judgments, separate from binary checks.

**Inter.** Rasmus Andersson’s exceptionally controlled spacing and tall x-height make it a reliable interface and long-text workhorse; its neutral voice can feel generic in expressive display work. `tnum` is available, with proportional numerals as the default.

**Mona Sans.** Degarism Studio and GitHub made a broad, lively grotesk: its width axis and alternate forms give display and headings character while regular text stays steady. The full width-variable file costs more than a stripped weight-only build, and the `Mona` RFN complicates name-preserving subsetting. `tnum` is available.

**Hubot Sans.** The same team’s more mechanical drawing is unusually effective for large, compact headlines; its angular details and tight rhythm tire in paragraphs. Its width axis is the main reason to choose it. `tnum` is available.

**DM Sans.** Colophon Foundry’s optical-size axis keeps small text practical while giving larger sizes a cleaner rhythm; the display end is restrained, not a strong editorial signature. Default numerals are proportional, with no `tnum` feature in the checked files.

**Public Sans.** Built for public-facing interfaces, Public Sans is plain, robust and well spaced from labels through reading text. It offers little drama at 100 px. It has `tnum`, `lnum` and `onum`.

**IBM Plex Sans.** Bold Monday’s industrial humanism has careful differentiation and a useful condensed width range, making it especially good for dense interfaces. Its technical personality is unmistakable and the full file is heavier than the leaner sans choices. Default figures are tabular; `lnum` and `onum` are present.

**Source Sans 3.** Paul D. Hunt’s humanist forms and long family development yield relaxed, highly readable paragraphs and clear UI labels. Its open texture is less striking for display. Default digits are tabular; the upright has `smcp`/`c2sc` and both have `onum`.

**Work Sans.** Wei Huang’s family is unusually complete for a web workhorse: text spacing, italics, small caps, figure styles and wide weights are all present. The heavier, larger settings are less distinctive than dedicated display faces. Both files have `smcp`, `c2sc`, `tnum`, `lnum` and `onum`.

**Noto Sans.** Its broad multilingual engineering and sober drawing make Noto Sans dependable when copy expands beyond Western Latin. At 883.0 KB for the complete upright file, it is expensive as a default Latin web font. It has small caps and complete figure-style features.

**Atkinson Hyperlegible Next.** Letters From Sweden’s revision for the Braille Institute gives similar characters deliberate distinctions that hold up at small sizes. The conspicuous shapes and loose rhythm can dominate a large headline. `tnum` is available.

**Red Hat Text.** MCKL tuned this compact, friendly family for text sizes; it remains crisp in labels and moderate headings. Its limited 300–700 range and modest display presence make it a companion rather than the sole expressive face. `tnum` is available.

**Red Hat Display.** MCKL’s companion has confident large-size proportions and a broad enough weight range for headlines. Those display proportions are less comfortable in long 15 px reading. `tnum` is available.

**Instrument Sans.** Rodrigo Fuenzalida and Jordan Egstad’s narrow-to-normal width axis gives concise editorial headings a distinctive, controlled shape. The 400–700 weight span is narrow for a general-purpose body family. `tnum` is available.

**Screened out:** Figtree, Geist, Manrope, Schibsted Grotesk, Hanken Grotesk and Albert Sans do have licensed weight-variable files and Swedish coverage. They are competent, but add less range to this already crowded category than the retained text, interface and display specialists. Manrope has no variable italic in the checked release.

**Lora.** Cyreal’s contemporary calligraphic serif has warm, sturdy text colour and a genuine italic; it works particularly well in reading copy and medium headings. Its 400–700 range limits very light or very heavy display treatments. `tnum` is available; the `Lora` RFN applies.

**Source Serif 4.** Frank Grießhammer’s optical masters (8–60) and carefully spaced text shapes make it the most versatile serif here, from small reading to headlines. The complete upright file is substantial, and the upright has small caps while the checked italic lacks `smcp`. Default figures are tabular; `lnum` and `onum` are present.

**Newsreader.** Production Type drew its optical sizes for sustained screen reading, with generous text forms and graceful display cuts. At very small sizes it needs enough line spacing, and its quieter personality may underplay a forceful brand. Default figures are tabular, with `tnum`/`pnum`.

**Literata.** TypeTogether’s book-face discipline, large optical span and true italics make it excellent for long-form reading. The full files are relatively large and the display setting is dignified rather than flamboyant. Both styles include small caps and full figure-style features.

**Fraunces.** Undercase Type’s expressive, soft oldstyle is one of the strongest display choices; `SOFT` and `WONK` change its mood without swapping families. Its lively texture and eccentric forms are tiring for long body copy. The checked files lack `tnum`, `lnum` and small-cap tags.

**EB Garamond.** Georg Duffner and Octavio Pardo’s Garamond revival has fine historical texture, a true italic and a rich set of small-cap and figure features. The delicate strokes are less robust in small low-resolution UI labels. Default figures are tabular.

**Noto Serif.** Its steady letterforms and huge language coverage make it a safe multilingual reading serif. The complete Latin-plus-script file is much heavier than the other text serifs and has less individual voice. Default digits are tabular; both styles have small caps and figure alternatives.

**Bodoni Moda.** Owen Earl’s optical-size treatment gives high-contrast display typography a striking, polished range, including proper italics and small caps. Thin hairlines require care on small screens, so it is not the default 15 px body choice. `tnum`, `lnum` and `onum` are available.

**Alegreya.** Juan Pablo del Peral’s literary rhythm and carefully drawn italics make Alegreya a strong alternative for long text; its lively forms also hold medium headings. It lacks the large display shock of Bodoni or Fraunces. Both styles have small caps and full numeral options.

**Playfair.** Claus Eggers Sørensen’s high-contrast design and extremely broad optical axis are memorable at large sizes. The fine strokes and strong contrast make sustained small-screen reading a poor fit; the complete variable file is also large. Both styles have small caps and full numeral options.

**STIX Two Text.** Tiro Typeworks’ scholarly family has disciplined serif text, a good italic and small caps, with a particularly broad technical character repertoire. Its academic tone is cooler than Lora or Alegreya, and it is not a strong brand display face. Default digits are tabular; `onum` is available.

**Screened out:** Crimson Pro, Merriweather, Gelasio, Libre Caslon Text, Vollkorn, Cormorant Garamond and Libre Baskerville have eligible variable files; they are good designs but overlap the stronger text or display choices here. Merriweather’s complete upright variable file alone measures 2,460.6 KB. Libre Baskerville lacks tabular figures.

**Red Hat Mono.** MCKL’s compact, calm mono is especially good for short metadata and code that should not overwhelm the main family. Its weight span stops at 700 and its compact forms have less display character. Monospaced digits are tabular by default.

**JetBrains Mono.** JetBrains’ enlarged x-height and differentiated symbols make long code sessions comfortable; the real italic and coding alternates are substantial assets. Its relatively wide, assertive texture can make tiny uppercase labels heavy. Digits are tabular by default.

**IBM Plex Mono.** Bold Monday’s IBM companion has precise, slightly industrial punctuation and a newly published official variable roman and italic. It pairs naturally with Plex Sans, although its 100–700 ceiling is lower than several peers. Default digits are tabular; `lnum`, `onum` and many stylistic sets are available.

**Source Code Pro.** Paul D. Hunt’s restrained mono has excellent code rhythm and a true italic without distracting ligatures. At tiny label sizes its relatively open, conventional texture is less compact than Red Hat Mono. Default digits are tabular; `onum` is available.

**Commit Mono.** Eigil Nikolajsen gives code a quiet, narrow rhythm and many character alternates; the single variable file can move between roman and italic through `ital`. Its smaller design practice and unusual default weight of 200 warrant testing in the intended UI. Digits are tabular by default.

**Recursive.** Stephen Nixon’s five axes let the same expertly drawn design move from mono to casual and from upright to cursive slant; it is a powerful expressive code and label choice. The full file is large and the control surface is more complex than a simple dropdown. Digits are tabular at the mono default.

**Fira Code.** Nikita Prokopov’s careful ligatures make common programming sequences coherent without changing the underlying characters. There is no variable italic in the checked release, and ligatures can confuse readers who expect literal punctuation. Digits are tabular by default.

**Noto Sans Mono.** Noto’s symbol and language coverage is unusually dependable for international code and metadata. The full variable file is 732.1 KB and has no italic, so it is expensive for ordinary short labels. Digits are tabular; small caps and oldstyle figures are available.

**Screened out:** Geist Mono and Roboto Mono pass the binary and licence checks, but bring less distinct value than the retained compact, coding, multilingual and axis-rich choices. Inconsolata and Martian Mono also qualify technically; they are fine specialists, but the dropdown already has stronger general code companions.

## Near misses

- **Instrument Serif:** excellent sharp editorial display design by Rodrigo Fuenzalida and Jordan Egstad, but [Google Fonts publishes only Regular and Italic static TTFs](https://github.com/google/fonts/tree/main/ofl/instrumentserif); no `fvar` weight axis.
- **Zilla Slab:** Typotheque’s characterful slab, but [all published Google Fonts files are static weights](https://github.com/google/fonts/tree/main/ofl/zillaslab); no variable file.
- **Arvo:** Anton Koovit’s sturdy slab holds up in short text, but the [published files](https://github.com/google/fonts/tree/main/ofl/arvo) are static.
- **Libre Caslon Display:** a refined display cut, but the [published file](https://github.com/google/fonts/tree/main/ofl/librecaslondisplay) is static. Libre Caslon Text is variable, but is a separate family.
- **Spectral and Alegreya Sans:** strong text families by Production Type and Juan Pablo del Peral, respectively; the checked [Spectral](https://github.com/google/fonts/tree/main/ofl/spectral) and [Alegreya Sans](https://github.com/google/fonts/tree/main/ofl/alegreyasans) directories contain static instances only.

The remaining proposed slabs—[Solway](https://github.com/google/fonts/tree/main/ofl/solway), [Sanchez](https://github.com/google/fonts/tree/main/ofl/sanchez) and [Crete Round](https://github.com/google/fonts/tree/main/ofl/creteround)—also publish only static instances in the checked repository, and did not clear the editorial bar for the table.

The absent italic in Roboto Slab, Hepta Slab, Fira Code or Noto Sans Mono is a limitation, **not** a disqualifier: the requirement asks for a real variable weight axis and for italic availability to be reported, not for every family to have an italic. The same applies to monospaces whose default figures are tabular without a `tnum` switch.

Because the complete files are large, load only a chosen family and style; the table sizes are not a total page-weight estimate.

## Decision

This report was written before the owner added a requirement: real italics. Every shipped typeface needs an italic drawn by its designers, or a sloped cut they drew to serve as one; a browser's synthesised slant is never acceptable. That overrules the note under Near misses, removes Roboto Slab, Hepta Slab, Fira Code and Noto Sans Mono, and brings back Aleo, which has a variable italic, as the second slab serif. The upright and italic of every candidate were compared side by side in Firefox before choosing.

The owner's own study of 2026-11-03 then settled the list, its order and the best source for each typeface, overruling this report's sources and picks. The upstream file is not always best: Aleo's newest upstream file has lost glyphs, Red Hat's upstream 5.0.0 moves the named weights along the axis, Hubot Sans's release is older than Google Fonts', and EB Garamond's current Google Fonts build substitutes symbols by default, so a 2021 build is used. A family download from Google Fonts is complete; the web files its CSS serves, and Fontsource's, are stripped of stylistic sets and alternates.

Google Sans Flex, Roboto Serif and Noto Sans are subset to Latin to reduce their size, keeping their axes and features. Merriweather is as large, but its licence reserves the name, so it stays whole. Mona Sans Mono is not on the owner's list; it comes with Mona Sans and is a new design's monospace. `bin/design-fonts` holds the list; the table is what it fetched.
